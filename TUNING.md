# Настройка: где что крутится

Справочник для быстрой правки баланса и поведения. Отвечает на один вопрос:
**«хочу изменить вот это — куда лезть и как проверить»**.

Замысел игры — [project.md](project.md). Числа и источники баланса —
[BALANCE.md](BALANCE.md). Ростер ролей — [ROLES.md](ROLES.md).
Что уже собрано — [GAMEPLAY.md](GAMEPLAY.md). Замеры кадра — [PERFORMANCE.md](PERFORMANCE.md).

---

## 0. Правило, из которого всё остальное

**Числа живут в ассетах, а не в коде.** Значение по умолчанию в `.cs` —
это значение для *нового* поля и для *нового* ассета. В уже созданный
`RunConfig.asset` оно **не попадает никогда**: Unity дописывает новое поле
дефолтом один раз, при первом импорте, и дальше файл живёт своей жизнью.

Отсюда главная ошибка при настройке: поправить дефолт в коде, пересобрать,
не увидеть разницы и решить, что механика не работает. Правильно — писать
в ассет: руками в инспекторе или из кода через `AssetDatabase.LoadAssetAtPath`
+ `EditorUtility.SetDirty` + `SaveAssets`.

**Сцена забега и сцена стенда используют РАЗНЫЕ файлы настроек.**
Правка `RunConfig.asset` на стенде не видна, и наоборот. См. §5.

## 2. Класс бойца: `Classes/<Имя>.asset`

Один ассет = один класс. Поля сгруппированы заголовками; **пустая группа
значит «этой механики у класса нет»** — включается она не галкой, а
ненулевым значением. Это сделано нарочно: галка и число рассинхронизируются,
а «ноль = выключено» соврать не может.

### 2.1. Общее для всех

| Поле | Смысл |
|---|---|
| `displayName` | имя на карточках и на стенде |
| `prefab` | префаб с компонентом `Survivor` |
| `role` | `Melee` / `Ranged` / `Support` — **определяет кольцо в строю** и ряд на стенде |
| `aimYawOffset` | доворот корпуса под позу прицеливания, градусов. Только для стрелков; у копа 46 |
| `maxHealth`, `damage`, `attackRange`, `attackInterval` | основа боя |
| `attackAnimationSpeed` | множитель скорости замаха сверху подгонки под темп |
| `offerInTierUp` | попадает ли класс в карточки тир-апа |
| `icon` | портрет для стенда; печётся кнопкой, руками не заполнять |

### 2.2. Что включает какую механику

Роль — не «другой урон», а другой способ его нанести. Механика включается
ненулевым полем:

| Механика | Включает | Ключевые поля | Пример (класс, значения) |
|---|---|---|---|
| Удар по площади | `splashRadius > 0` | `shockShape` (круг/сектор), `shockAngle`, `shockImpact` (нокбэк/стан), `stunChance`, `stunDuration` | Молотобоец: 5 м, сектор 90°, стан 25% на 1.2 с |
| Удар по линии | `pierceWidth > 0` | `pierceLength`, `pierceMaxTargets` | Копейщик: коридор 1.4×5 м, до 3 целей |
| Цепная молния | `chainTargets > 0` | `chainJumpRange`, `chainFalloff`, `chainColor` | Электрик: 4 цели, перескок 3 м, спад 25% |
| Струя огня | `coneAngle > 0` | `coneRange`, `coneTipDamage`, `burnDuration`, `burnDamagePerSecond` | Огнемётчик: 55°, 5.5 м, на конце 35% урона, горение 3 с по 4 |
| Щит | `shieldEveryNth > 0` | `shieldArc`, `shieldRange`, `shieldMaxTargets`, `shieldPush`, `shieldDamageScale` | Щитоносец: каждый удар, дуга 110°, 5 м, 1 цель |
| Болт | `boltPierce > 0` | `boltRange` | Арбалетчик: 3 цели, 14 м |
| Очередь | `burstCount > 0` | `burstInterval` | ПП-шник: 4 выстрела с шагом 0.08 с |
| Ракета | `blastRadius > 0` | `knockbackDistance`, `knockbackDuration` | Ракетчик: взрыв 4.5 м |
| Лечение | `healPerTick > 0` | `healInterval` | Медик: 15 раз в 2 с |
| Крупный снаряд | `shotScale ≠ 1` | — | Снайпер: 2.4; ПП-шник: 0.8 |

**Ближний бой:** `attackHitTime` — доля замаха, на которой наступает
попадание (0.5 = середина). Урон наносится не в момент нажатия, а здесь,
иначе враг отлетает раньше, чем оружие до него дошло.

### 2.3. Ауры саппортов

Пять полей, каждое даёт «класс-ауру». Все считаются **по живым** бойцам
и **складываются, а не перемножаются**: игрок должен уметь посчитать
в уме, что даст следующий такой боец.

| Поле | Что множит | Кто носит | Значение |
|---|---|---|---|
| `squadSpeedPerUnit` | скорость отряда | Носильщик | 0.06 |
| `sparkRadiusPerUnit` | радиус **притяжения** искр | Разведчик | 0.25 |
| `squadDamagePerUnit` | урон всего отряда | Тренер | 0.10 |
| `squadAttackSpeedPerUnit` | темп атаки (делит паузу) | Кофевар | 0.10 |
| `sparkValuePerUnit` | опыт с каждого подбора | Делец | 0.15 |

Три вещи, которые важно не сломать:

- Ауры множатся **отдельно** от вложенного игроком в класс
  (`DamageBonusFor`), иначе прокачка тренера растворяется в прокачке стрелков.
- Разгон атаки **делит паузу**, а не множит урон: иначе кофевар и тренер
  складываются в одно число и выбор между ними исчезает.
- Бафф урона **не касается лечения**. Медик лечит, а не бьёт.

Карточка тир-апа подписывается автоматически по тому, что класс делает:
лечение → «лечения», скорость → «скорости», сбор → «сбора», урон отряду →
«к баффу», темп → «к темпу», навар → «к навару», иначе «урона»
(`RunController.UpgradeNoun`).

### 2.4. Дуга замаха

`showAttackArc` + `arcDegrees`/`arcInner`/`arcStretch`/`arcHeight`/`arcTilt` —
подсветка сектора под ногами у ближнего боя. Чистая косметика.

## 3. Сцена: `RunConfig.asset` (и `BenchRunConfig.asset`)

Секции инспектора совпадают с заголовками в `ArenaConfig.cs`:

| Секция | Что настраивает |
|---|---|
| Камера, Свет | наклон, дистанция, цвета освещения |
| Отряд | `squadComposition` (стартовый состав), `squadSpeed`, строй: `formationRing*`, `separationRadius`, `memberSpeedMultiplier`, ссылка `bench` |
| Бой выжившего, Здоровье выжившего | пороги наведения, полоски HP |
| Зомби | скорость, урон, HP по тирам, время трупа, скорость смерти |
| Спавн | радиусы и правила появления |
| Забег | `runWaves[]`, `waveBreak`, `squadSlotCap` |
| Тир-ап | цена, варианты, шаги улучшений, **все настройки искр** |
| Эффекты | по секции на каждый: ударная волна, ракета, болт, звёзды стана, пламя, молния, трассеры, плевок, виньетка |
| Кадр, Замер кадра, Стенд нагрузки | ограничение FPS, счётчики, прогон нагрузки |
| Звук | громкость выстрелов и ударов |
| Отладка стенда | `debugSquadInvincible`, `debugAutoDrive`, `debugAutoDriveRadius` |

### 3.1. Волна: `runWaves[]`

`Name`, `Duration`, `SpawnInterval`, `GroupMin/Max`, `MinTier/MaxTier`,
`MaxAlive`. Сейчас три волны: 20 с (тир 1, до 14 живых), 75 с (тир 2, до 40),
120 с (тиры 2–3, до 40).

`MaxAlive` — не баланс, а бюджет кадра: цена зомби измерена и линейна,
см. [PERFORMANCE.md](PERFORMANCE.md) §6. Поднимать, только сверившись с замером.

### 3.2. Искры и тир-ап

Текущие значения: `sparkPerKill` 1, цена тир-апа 8 × 1.15 за каждый взятый,
3 варианта, шанс пополнения 0.5, шаг урона 0.2, шаг здоровья 0.25.
Разлёт 3–6 м, притяжение 2.5 м, касание 1.2 м, потолок поля 150.

Три правила, встроенные в код и легко ломаемые правкой «по вкусу»:

1. **Разлёт считается от центра отряда**, а не от трупа. Раньше складывался
   с местом смерти: погиб в 4 м — бутылка улетала на 7–10, и притяжение
   не доставало никогда.
2. **Вытесненная потолком искра пропадает, не засчитываясь.** Иначе
   неподвижный отряд со снайперами получает тир-апы сам собой.
3. **Надбавка дельца копится дробями.** Бутылка стоит единицу, и без
   накопления остатка прибавка исчезает в округлении.

## 4. Строй

Роль решает кольцо: `Melee` внутрь, `Ranged` дальше, `Support` в центр —
самое защищённое место. Радиус слота считается по **самому крупному**
классу в отряде (по скиннингу, без оружия: полутораметровая лопата
на кости руки раздувала строй в разы).

Правки: `formationRingSpacingMin`, `formationRingSpacingStep`,
`formationRingGap`, `separationRadius`. `memberSpeedMultiplier` — насколько
боец быстрее отряда, когда догоняет свой слот.

## 5. Стенд

**Сцена `Bench.unity`** — копия забега со своим `BenchRunConfig.asset`.
Правки на стенде забег не трогают, и наоборот. У забега поле `bench` пустое,
у стенда — ссылка на `BenchConfig.asset`.

`BenchConfig.asset`:

| Поле | Смысл |
|---|---|
| `askOnStart` | показывать экран сборки перед забегом |
| `classes` | что показывать; заполняется меню `WarfareSurvivor → Стенд → Собрать все классы` |
| `maxPerClass` | потолок на класс (12) |
| `minTotal` | сколько набрать, чтобы кнопка «В бой» ожила |
| `lastPick` | память последнего набора, пишется при старте |

Набранное на стенде идёт **мимо** `squadComposition` — через
`SquadController.SpawnFrom`. Отряд не создаётся, пока экран открыт:
`Awake` возвращается ни с чем, `RunController` держит `Time.timeScale = 0`
и не начинает волну.

**Новый класс на стенде** — два шага: «Собрать все классы», затем
«Испечь иконки классов». Иконка — снимок модели в позе из её же Idle;
без этого шага карточка рисует серую заглушку.

## 6. Как проверять правки

Механику **нельзя принимать на глаз** — почти каждая ошибка в этом проекте
выглядела как «работает, но слабо». Рабочие приёмы:

| Что проверяем | Как |
|---|---|
| Урон/темп бойца | отражением читать `Survivor.Damage` и `AttackInterval` (оба private) |
| Ауры | `squad.SpeedMultiplier`, `DamageMultiplier`, `AttackSpeedMultiplier`, `SparkRadiusMultiplier`, `SparkValueMultiplier` |
| Темп атаки в бою | временный статический счётчик атак в `Survivor.Attack`, два окна по 45–60 с: с аурой и без |
| Радиус сбора | положить искру ровно в N метрах от ближайшего бойца, вызвать приватный `SparkField.Update` один раз и прочитать флаг `Flying`; порог искать вилкой |
| Ценность подбора | вызвать приватный `CollectAt` сто раз по бутылке в 1 очко и сравнить с `RunController.Sparks` |
| Попадания в движении | включить `debugAutoDrive`, считать попадания, а не смотреть |
| Раскладка интерфейса | `LayoutRebuilder.ForceRebuildLayoutImmediate`, затем `GetWorldCorners` и сравнить **с размером канвы** |

### 6.1. Ловушки замера (все проверены на своей шкуре)

- **`Time.deltaTime` внутри eval равен нулю.** Снаряды и таймеры вручную
  не шагают: нужны настоящие кадры между вызовами.
- **На экране тир-апа `Time.timeScale = 0`** — любой замер во время выбора
  показывает мёртвую картинку.
- **`Screen.height` в редакторе — высота окна, а не Game View.** Проверять
  раскладку по нему бессмысленно; сравнивать надо с прямоугольником канвы.
- **Скриншот игры не содержит интерфейса**: захват идёт мимо оверлея.
  Чтобы снять UI, канву переводят в `WorldSpace` и снимают отдельной
  камерой в стороне от арены.
- **Спавнер снимается с паузы сам** при начале следующей волны. Замер
  «в одну мишень» после этого считает не то, что задумано.
- **Волна кончается — поле искр подметается целиком** (`CollectAll` по всему,
  что в кадре). Сравнение «собрано/лежит» через границу волны бессмысленно.
- **Буфф зомби на тесте убивает свой же отряд** быстрее, чем идёт замер;
  для долгих окон включать `debugSquadInvincible`.
- **`Registry.Zombies` нельзя перебирать вперёд, если по ходу его меняешь** —
  каждый второй пропускается. Идти назад.

### 6.2. После замера

Вернуть всё, что трогал: отладочные галки (`debugSquadInvincible`,
`debugAutoDrive`), временные счётчики, тестовый состав отряда,
подкрученные значения классов. Тестовый состав в конфиге — самая частая
забытая правка перед сборкой на устройство.

## 7. Синергии

`Synergies/*.asset`: знак (плюс/минус/другое), параметр из перечисления
`SquadStat`, величина. Класс держит список своих синергий в поле `synergies`.

**Ни один параметр пока не подключён к бою** — система собрана как настройка.
Библиотека синергий (`WarfareSurvivor → Синергии`) печатает у каждого
параметра пометку, читает его кто-нибудь или нет, и что нужно сделать,
чтобы читал. Параметры сделаны перечислением, а не ассетами, именно затем:
ассет-параметр позволил бы завести настройку, которая молча ничего не делает.

Три параметра сейчас подключить дешевле всего — под них уже есть множители
у отряда: `MoveSpeed`, `AttackSpeed` и урон.
